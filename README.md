# Blue Me

سامانه یکپارچه و فارسی مدیریت کسب‌وکار برای کافه، رستوران، فست‌فود و مجموعه‌های مشابه. Blue Me یک نمونه نمایشی نیست؛ سفارش، موجودی، قیمت، دستور پخت، درخواست خرید، گزارش مدیریتی و گزارش فعالیت‌ها همگی به پایگاه داده واقعی متصل‌اند.

## امکانات فعلی

- رابط کاملاً فارسی، راست‌چین، واکنش‌گرا و مناسب دسکتاپ، تبلت و موبایل
- برند، نام کسب‌وکار، رنگ اصلی، شعار و لوگوی قابل تنظیم از `.env`
- احراز هویت امن با رمز هش‌شده و نقش‌های `مدیر کل`، `مدیر انبار`، `مدیر حسابداری`، `مدیر فروش` و `مدیر آشپزخانه`
- ساخت و غیرفعال‌سازی حساب مدیران توسط مدیر کل
- انبار دسته‌بندی‌شده با جست‌وجو، تصویر کالا، ورود/اصلاح/ضایعات، میانگین موزون هزینه و هشدار نقطه سفارش
- تغییر قیمت مدیر انبار فقط پس از تأیید مدیر کل
- گزارش اختصاصی کالا شامل ارزش موجودی، مصرف ۹۰ روزه، روزهای باقی‌مانده، گردش و تاریخچه قیمت
- صندوق فروش سریع، مشتری شناخته‌شده یا مهمان، تخفیف، روش پرداخت و توضیح هر قلم
- رسید جداگانه فارسی برای مشتری و فیش آشپزخانه با چاپ ۸۰ میلی‌متری
- کسر اتمیک مواد اولیه از انبار بر اساس دستور پخت و بازگردانی موجودی هنگام لغو مجاز سفارش
- دستور پخت دقیق با مقدار، واحد، خروجی، زمان، مراحل و محاسبه هزینه هر پرس و درصد هزینه مواد
- برد زنده آشپزخانه و درخواست نیازهای فردا با اولویت و تأیید مدیر کل
- داشبورد اصلی با فروش، سفارش، صف آشپزخانه، موجودی و تصمیم‌های در انتظار
- گزارش‌های حرفه‌ای فروش، رشد، سود، حاشیه، ساعات اوج، محصولات برتر، ترکیب درآمد، مشتری و سلامت انبار
- گزارش فعالیت دقیق و قابل فیلتر بر اساس کاربر، دسته، عملیات، تاریخ و متن
- MySQL/MariaDB با Alembic، ایندکس‌های عملیاتی، بکاپ قابل بازیابی و راه‌اندازی daemon با systemd یا Docker Compose

## راه‌اندازی سریع

برای نصب جدید کافی است اجرا کنید:

```bash
chmod +x start.sh
./start.sh
```

اگر `.env` وجود نداشته باشد، اسکریپت اطلاعات کسب‌وکار، برند، حساب مدیر کل و نوع MySQL را به‌صورت تعاملی می‌پرسد. دو حالت وجود دارد:

1. `external`: استفاده از MySQL موجود. در سیستمی که Docker Compose ندارد، یک سرویس systemd کاربری ساخته و فعال می‌شود.
2. `managed`: ساخت MySQL 8.4، API و وب به‌صورت سرویس‌های Docker Compose با `restart: unless-stopped`.

فرمان‌های روزمره:

```bash
./start.sh --status
./start.sh --logs
./start.sh --stop
./start.sh --configure
```

در نصب فعلی، آدرس سامانه `http://127.0.0.1:3100` است. نام کاربری مدیر کل در `ROOT_USERNAME` و رمز اولیه آن در `ROOT_PASSWORD` فایل `.env` نگهداری می‌شود. فایل `.env` در Git ثبت نمی‌شود و سطح دسترسی آن باید `600` بماند.

## تنظیم برند برای هر کسب‌وکار

مقادیر زیر را پیش از اولین اجرا یا با `./start.sh --configure` تنظیم کنید:

```dotenv
APP_NAME=Blue Me
BUSINESS_NAME=نام کسب‌وکار
BRAND_TAGLINE=مدیریت شفاف، تصمیم‌گیری هوشمند
BRAND_PRIMARY_COLOR=#2563eb
BRAND_LOGO_URL=/brand/logo.png
APP_LOCALE=fa
CURRENCY_LABEL=تومان
```

برای لوگوی محلی، فایل را مثلاً در `branding/logo.png` قرار دهید و `BRAND_LOGO_URL=/brand/logo.png` بگذارید. استفاده از URL کامل HTTPS نیز ممکن است. خالی بودن لوگو مجاز است و نشان پیش‌فرض نمایش داده می‌شود.

## تنظیم MySQL موجود

نمونه تنظیم یک سرور موجود:

```dotenv
DATABASE_MODE=external
DATABASE_HOST=localhost
CONTAINER_DATABASE_HOST=host.docker.internal
DATABASE_PORT=3306
DATABASE_NAME=blue_me
DATABASE_USER=your_user
DATABASE_PASSWORD=your_password
```

`CONTAINER_DATABASE_HOST` فقط برای اجرای API داخل کانتینر استفاده می‌شود. اگر MySQL روی همان میزبان Docker است، `host.docker.internal` مقدار مناسب است. پایگاه داده باید `utf8mb4` باشد؛ مهاجرت‌ها با Alembic خودکار اجرا می‌شوند.

## نقش‌ها و دسترسی‌ها

| نقش | دسترسی اصلی |
|---|---|
| مدیر کل | تمام بخش‌ها، کاربران، تأیید قیمت و خرید، گزارش‌ها و فعالیت‌ها |
| مدیر انبار | کالا، دسته‌بندی، تصویر، موجودی، هزینه و درخواست تغییر قیمت |
| مدیر حسابداری | مشتری، صندوق، ثبت سفارش، رسید و تکمیل/لغو سفارش مجاز |
| مدیر فروش | ثبت سفارش و مشتری در صندوق |
| مدیر آشپزخانه | برد سفارش، دستور پخت، محاسبه هزینه و نیازهای روزانه |

تمام عملیات حساس سمت سرور کنترل سطح دسترسی می‌شوند؛ پنهان بودن یک گزینه در رابط کاربری تنها لایه کنترل نیست.

## بکاپ

```bash
./scripts/backup.sh
```

خروجی فشرده در `backups/` ساخته می‌شود و اسکریپت پیش از اعلام موفقیت، فایل را با `gzip -t` بررسی می‌کند. مسیر دیگری نیز می‌توان داد:

```bash
./scripts/backup.sh /path/to/secure/backups
```

## توسعه و آزمون

Backend:

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements-dev.txt
PYTHONPATH=backend .venv/bin/pytest -q backend/tests
.venv/bin/ruff check backend/app backend/tests
```

Frontend:

```bash
npm install --prefix frontend
npm run dev --prefix frontend
npm run build --prefix frontend
npm run lint --prefix frontend
```

بررسی مهاجرت روی پایگاه تنظیم‌شده:

```bash
cd backend
../.venv/bin/dotenv -f ../.env run -- ../.venv/bin/alembic -c alembic.ini current
../.venv/bin/dotenv -f ../.env run -- ../.venv/bin/alembic -c alembic.ini check
```

```text
start.sh                 تنظیم، نصب، اجرا و مدیریت سرویس
```
