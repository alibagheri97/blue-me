# Shaverma-chi | شاورماچی

سامانه یکپارچه و فارسی مدیریت شاورماچی. Shaverma-chi یک نمونه نمایشی نیست؛ سفارش، موجودی، قیمت، دستور پخت، درخواست خرید، گزارش مدیریتی و گزارش فعالیت‌ها همگی به پایگاه داده واقعی متصل‌اند.

## امکانات فعلی

- رابط کاملاً فارسی، راست‌چین، واکنش‌گرا و مناسب دسکتاپ، تبلت و موبایل
- برند، نام کسب‌وکار، رنگ اصلی، شعار و لوگوی قابل تنظیم از `.env`
- احراز هویت امن با رمز هش‌شده و نقش‌های `مدیر کل`، `مدیر انبار`، `مدیر حسابداری`، `مدیر فروش` و `مدیر آشپزخانه`
- ساخت و غیرفعال‌سازی حساب مدیران توسط مدیر کل
- انبار دسته‌بندی‌شده با جست‌وجو، تصویر کالا، واحد مرجع، میانگین موزون هزینه و هشدار نقطه سفارش
- «ورودی کالا» چندقلمی با شماره رسید، فروشنده، فاکتور، تاریخ خرید، تخفیف، هزینه جانبی، تبدیل واحد و بهای تمام‌شده هر قلم
- سابقه کامل رسیدها و امکان ابطال کنترل‌شده توسط مدیر کل؛ هر ورود یا ابطال هم‌زمان موجودی، هزینه و گزارش فعالیت را به‌روزرسانی می‌کند
- تغییر قیمت مدیر انبار فقط پس از تأیید مدیر کل
- گزارش اختصاصی کالا شامل ارزش موجودی، مصرف ۹۰ روزه، روزهای باقی‌مانده، گردش و تاریخچه قیمت
- صندوق فروش سریع، مشتری شناخته‌شده یا مهمان، تخفیف، روش پرداخت و توضیح هر قلم
- رسید جداگانه فارسی برای مشتری و فیش آشپزخانه با چاپ ۸۰ میلی‌متری
- مدیریت منوی فروش در دو حالت «محصول آماده با دستور پخت» و «کالای مستقیم انبار» همراه با دسته‌بندی قابل مدیریت
- حالت «بیرون‌بر» در صندوق با تعداد بسته قابل تنظیم و تعریف ظرف، پاکت، دستمال و سایر ملزومات هر بسته از کالاهای واقعی انبار
- نمایش زنده هزینه، سود ناخالص، حاشیه سود، وضعیت موجودی و حداکثر تعداد قابل فروش برای هر آیتم منو
- کسر اتمیک مواد اولیه از انبار بر اساس دستور پخت یا مقدار کالای مستقیم و بازگردانی موجودی هنگام لغو مجاز سفارش
- دستور پخت دقیق با مقدار، واحد، خروجی، زمان، مراحل و محاسبه هزینه هر پرس و درصد هزینه مواد
- برد زنده آشپزخانه و فهرست خرید فردا با دو منبع دستی و خودکار، اولویت و تأیید مدیر کل
- حضور و غیاب دومرحله‌ای: ثبت فوری ساعت ورود، چک‌لیست الزامی پس از ورود و چک‌لیست تحویل پیش از خروج
- قرارداد پرداخت انحصاری برای هر پرسنل (حقوق ثابت یا درصد از سود)، دفتر امتیاز مثبت/منفی، امتیاز خودکار حضور و تسویه دوره‌ای
- ساخت خودکار نیاز خرید و اعلان مدیر کل هنگام رسیدن موجودی به حد سفارش؛ پیشنهاد خرید تا سطح هدف و بسته‌شدن خودکار پس از تأمین
- داشبورد اصلی با فروش، سفارش، صف آشپزخانه، موجودی و تصمیم‌های در انتظار
- گزارش‌های حرفه‌ای فروش، رشد، سود، حاشیه، ساعات اوج، محصولات برتر، ترکیب درآمد، مشتری و سلامت انبار
- گزارش فعالیت دقیق و قابل فیلتر بر اساس کاربر، دسته، عملیات، تاریخ و متن
- MySQL/MariaDB با Alembic، ایندکس‌های عملیاتی، بکاپ قابل بازیابی و راه‌اندازی daemon با systemd یا Docker Compose

## راه‌اندازی سریع

برای نصب جدید کافی است اجرا کنید:

```bash
chmod +x start.sh
./start.sh
```

اگر `.env` وجود نداشته باشد، اسکریپت اطلاعات کسب‌وکار، برند، حساب مدیر کل و نوع MySQL را به‌صورت تعاملی می‌پرسد. دو حالت وجود دارد:

1. `external`: استفاده از MySQL موجود. در سیستمی که Docker Compose ندارد، یک سرویس systemd کاربری ساخته و فعال می‌شود.
2. `managed`: ساخت MySQL 8.4، API و وب به‌صورت سرویس‌های Docker Compose با `restart: unless-stopped`.

فرمان‌های روزمره:

```bash
./start.sh --status
./start.sh --logs
./start.sh --stop
./start.sh --configure
```

در نصب فعلی، آدرس سامانه `http://127.0.0.1:3100` است. نام کاربری مدیر کل در `ROOT_USERNAME` و رمز اولیه آن در `ROOT_PASSWORD` فایل `.env` نگهداری می‌شود. فایل `.env` در Git ثبت نمی‌شود و سطح دسترسی آن باید `600` بماند.

## تنظیم برند برای هر کسب‌وکار

مقادیر زیر را پیش از اولین اجرا یا با `./start.sh --configure` تنظیم کنید:

```dotenv
APP_NAME=Shaverma-chi
BUSINESS_NAME=شاورماچی
BRAND_TAGLINE=مدیریت شفاف، تصمیم‌گیری هوشمند
BRAND_PRIMARY_COLOR=#2563eb
BRAND_LOGO_URL=/brand/logo.png
APP_LOCALE=fa
APP_TIMEZONE=Asia/Tehran
BUSINESS_DAY_START_HOUR=5
CURRENCY_LABEL=تومان
```

در تنظیم پیش‌فرض، روز کاری از ساعت ۰۵:۰۰ تا ۰۵:۰۰ روز بعد محاسبه می‌شود؛ بنابراین فروش‌های پس از نیمه‌شب تا قبل از ساعت ۰۵:۰۰ در آمار روز کاری قبل قرار می‌گیرند.

برای لوگوی محلی، فایل را مثلاً در `branding/logo.png` قرار دهید و `BRAND_LOGO_URL=/brand/logo.png` بگذارید. استفاده از URL کامل HTTPS نیز ممکن است. خالی بودن لوگو مجاز است و نشان پیش‌فرض نمایش داده می‌شود.

## تنظیم MySQL موجود

نمونه تنظیم یک سرور موجود:

```dotenv
DATABASE_MODE=external
DATABASE_HOST=localhost
CONTAINER_DATABASE_HOST=host.docker.internal
DATABASE_PORT=3306
DATABASE_NAME=blue_me
DATABASE_USER=your_user
DATABASE_PASSWORD=your_password
```

`CONTAINER_DATABASE_HOST` فقط برای اجرای API داخل کانتینر استفاده می‌شود. اگر MySQL روی همان میزبان Docker است، `host.docker.internal` مقدار مناسب است. پایگاه داده باید `utf8mb4` باشد؛ مهاجرت‌ها با Alembic خودکار اجرا می‌شوند.

## نقش‌ها و دسترسی‌ها

| نقش | دسترسی اصلی |
|---|---|
| مدیر کل | تمام بخش‌ها، کاربران، تأیید قیمت، نظارت و ابطال ورودی کالا، گزارش‌ها و فعالیت‌ها |
| مدیر انبار | کالا، دسته‌بندی، تصویر، ثبت ورودی، موجودی، هزینه و درخواست تغییر قیمت |
| مدیر حسابداری | مشتری، صندوق، منوی فروش، ثبت سفارش، رسید و تکمیل/لغو سفارش مجاز |
| مدیر فروش | منوی فروش، ثبت سفارش و مشتری در صندوق |
| مدیر آشپزخانه | برد سفارش، دستور پخت، محاسبه هزینه و نیازهای روزانه |

تمام عملیات حساس سمت سرور کنترل سطح دسترسی می‌شوند؛ پنهان بودن یک گزینه در رابط کاربری تنها لایه کنترل نیست.

## حقوق، سهم سود و امتیاز پرسنل

بخش «حقوق و امتیاز» فقط برای مدیر کل قابل مشاهده است. برای هر همکار دقیقاً یکی از این دو قرارداد انتخاب می‌شود:

1. `حقوق ثابت`: مبلغ ثابت دوره تسویه.
2. `درصد از سود`: درصدی از سود ناخالص معتبر همان دوره؛ سود از فروش منهای بهای ثبت‌شده مواد و بسته‌بندی محاسبه می‌شود و غذای پرسنلی، سفارش لغوشده و سفارش حذف‌شده در آن نیست.

ارزش ریالی هر امتیاز جداگانه برای هر پرسنل تنظیم می‌شود. ثبت ورود، تکمیل چک‌لیست شروع، ثبت خروج، تکمیل چک‌لیست پایان و هر ساعت کامل حضور می‌توانند امتیاز خودکار داشته باشند؛ مدیر کل نیز با دلیل اجباری امتیاز تشویقی یا منفی ثبت می‌کند. صورت‌حساب دوره به‌صورت snapshot ذخیره می‌شود تا تغییر بعدی قرارداد یا امتیاز، سابقه تسویه‌شده را تغییر ندهد.

چک‌لیست‌های هر کاربر از داشبورد مدیر کل و بخش «چک‌لیست اختصاصی حضور پرسنل» تعریف می‌شوند. در زبانه اول مواردی قرار می‌گیرند که پس از ثبت ساعت ورود و پیش از بازشدن فضای کاری باید انجام شوند؛ زبانه دوم موارد اجباری تحویل پایان کار را پیش از ثبت خروج نگه می‌دارد.

## چرخه کالا، فروش و سود

چرخه عملیاتی سیستم به این صورت است:

1. در «ورودی کالا» برای هر قلم فقط مقدار، واحد و مبلغ کل خرید ثبت می‌شود؛ برای نمونه `۵ کیلوگرم گوشت با مبلغ ۱٬۰۰۰٬۰۰۰ تومان`. تبدیل آن به `۵۰۰۰ گرم` و بهای هر گرم در پشت صحنه انجام می‌شود و کاربر با ضریب فنی سروکار ندارد.
2. هزینه جانبی و تخفیف رسید متناسب با مبلغ اقلام سرشکن می‌شود و میانگین موزون بهای موجودی به‌روزرسانی می‌گردد.
3. در «مدیریت منو»، نوشیدنی و آب می‌توانند مستقیم به یک کالای انبار متصل شوند. غذاهای آماده با دستور پخت دقیق به مواد اولیه متصل می‌شوند.
4. هنگام ثبت سفارش، مقدار لازم در همان تراکنش از انبار کم و بهای تمام‌شده همان لحظه روی سفارش ثبت می‌شود؛ بنابراین تغییر قیمت خریدهای آینده سود تاریخی را عوض نمی‌کند.
5. برای سفارش بیرون‌بر، از «مدیریت منو ← بسته‌بندی بیرون‌بر» کالاهای هر بسته و مقدار دقیق آن‌ها را تعریف کنید. سیستم این مقادیر را در تعداد بسته ضرب می‌کند، همراه مواد غذا از انبار کم می‌کند و هزینه آن را در سود واقعی لحاظ می‌کند.
6. اگر موجودی از حد سفارش کمتر شود، سیستم نیاز خودکار خرید فردا و اعلان مدیر کل را می‌سازد. مقدار پیشنهادی برابر فاصله تا سطح هدف است و پس از تأمین، نیاز خودکار بسته می‌شود.

برای فعال‌سازی خرید خودکار یک کالا، در فرم انبار «حد سفارش»، «سطح هدف» و گزینه «افزودن خودکار به خرید فردا» را تنظیم کنید. سطح هدف باید از حد سفارش بیشتر باشد. دسته‌های انبار و منو از داخل همان بخش‌ها قابل افزودن و حذف هستند؛ دسته استفاده‌شده تا زمان جابه‌جایی اقلام حذف نمی‌شود.

## کاتالوگ اولیه شاورما

فرمان زیر نمونه‌های مواد اولیه و محصولات درخواست‌شده را به‌صورت تکرارپذیر ایجاد می‌کند:

```bash
cd backend
../.venv/bin/dotenv -f ../.env run -- ../.venv/bin/python -m app.cli seed-catalog
```

این فرمان ۴۱ کالای انبار در ۸ دسته (شامل پنج قلم اولیه بسته‌بندی بیرون‌بر) و ۲۳ آیتم منو در ۵ دسته ایجاد می‌کند. قیمت خرید کالاهای انبار صفر می‌ماند تا پس از ثبت ورودی واقعی محاسبه شود؛ محصولات منو با قیمت و دستور پایه شاورماچی آماده می‌شوند و بعداً قابل اصلاح‌اند. اجرای دوباره فرمان، داده تکراری ایجاد نمی‌کند و تغییرات دستی را حفظ می‌کند.

## بکاپ

```bash
./scripts/backup.sh
```

خروجی فشرده در `backups/` ساخته می‌شود و اسکریپت پیش از اعلام موفقیت، فایل را با `gzip -t` بررسی می‌کند. مسیر دیگری نیز می‌توان داد:

```bash
./scripts/backup.sh /path/to/secure/backups
```

## توسعه و آزمون

Backend:

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements-dev.txt
PYTHONPATH=backend .venv/bin/pytest -q backend/tests
.venv/bin/ruff check backend/app backend/tests
```

Frontend:

```bash
npm install --prefix frontend
npm run dev --prefix frontend
npm run build --prefix frontend
npm run lint --prefix frontend
```

بررسی مهاجرت روی پایگاه تنظیم‌شده:

```bash
cd backend
../.venv/bin/dotenv -f ../.env run -- ../.venv/bin/alembic -c alembic.ini current
../.venv/bin/dotenv -f ../.env run -- ../.venv/bin/alembic -c alembic.ini check
```

```text
backend/                 FastAPI، SQLAlchemy، Alembic و آزمون‌ها
frontend/                React، TypeScript، Vite و رابط فارسی RTL
branding/                فایل‌های لوگو و برند محلی
scripts/                 نصب systemd و بکاپ
docker-compose.yml       MySQL، API و Nginx برای نصب کانتینری
start.sh                 تنظیم، نصب، اجرا و مدیریت سرویس
```
